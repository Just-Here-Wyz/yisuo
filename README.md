# 译所 · 文献翻译工作台

> 不是一个「把文字丢给大模型」的翻译框，而是用**知识库**约束译法的文献翻译工作台：
> 译法原则 + 术语表 + 来源文献一起进提示词，保证术语与文风跨段落一致、可溯源。
> 纯前端 + 本地代理，API Key 只留在服务端。

---

## 它解决什么

直接拿 ChatGPT 翻论文会碰到三个问题：

1. **术语前后不一致**——同一个词这段译「贝叶斯推断」，下段译「贝叶斯推理」；
2. **段落错位**——长文一次性丢进去，模型会漏译、合并段落，甚至把第 3 段译成第 5 段；
3. **看不出依据**——某个专业词为什么这么译，翻完无从核对。

译所把这三件事分别交给：**术语表**（统一译法）、**编号协议**（锁住段落）、**权威注释**（标注依据来源）。

## 核心机制

| 机制 | 做法 |
|---|---|
| 段落编号协议 | 每段带 `<<<Pn>>>` 标记送入模型，要求按同一编号逐段返回，**一个都不能漏、不能合并、不能新增**；返回后按编号回填，顺序错乱可检出 |
| 三级解析降级 | 模型没按编号返回时，依次尝试编号解析 → 分段解析 → 整段兜底，不让格式抖动毁掉整篇译文 |
| 回声护栏 | 译文与原文归一化后逐字相同即判定「模型原样返回」，丢弃而不是当成译文写回 |
| 按段落切块 | 切块时绝不切断段落，按字符数或段数到顶即分段，避免句子被劈成两半 |
| 无需翻译判定 | 已经是中文的段落直接跳过，不浪费 token、也不让模型「改写」中文原文 |
| 术语标色 + 权威注释 | 命中术语表的词在译文里高亮，悬停显示依据（来源文献 / 译法原则） |

## 技术栈

- **前端**：原生 JS（无框架）+ pdf.js 解析 PDF，本地知识库快照 `kb-data.js`
- **代理**：Node 18+ 零依赖 HTTP 服务，`POST /api/translate` 转发到 OpenAI 兼容接口，**Key 不下发到浏览器**
- **文档转换**：Python + pdf2docx，PDF → DOCX 保留布局，失败时如实降级回原生解析
- **多模型**：智谱 GLM / DeepSeek / OpenAI / Moonshot / DashScope / 硅基流动，改一个环境变量即切换

## 快速开始

```bash
# 1. 配置密钥（Key 只在本地，不会进浏览器）
cp server/.env.example server/.env
#    编辑 server/.env，填入 TRANSLATE_API_KEY

# 2. 启动（零依赖，Node 18+）
node server/proxy.js
# 打开 http://localhost:8787
```

未配置 Key 时服务照常启动，`/api/health` 返回 `translatorReady: false`，前端自动退回**演示模式**——
不会白屏、不会静默失败。

## 测试

## 隐私与数据

- **API Key 只在服务端**：前端所有请求都走本地代理，浏览器里拿不到密钥。
- **文档不上传到任何第三方服务器**：仅转发给用户自己配置的模型服务商。
- **本地使用日志**：代理可选记录「原文 / 译文 / 时间 / 字符数」到本机 `data/usage.log`（JSONL），
  仅用于个人统计，不记录 IP 或账号；`data/` 已在 `.gitignore` 中排除，导出接口需 `ADMIN_TOKEN` 才可用，
  未设置时直接拒绝。
- 翻译结果是否准确仍需人工复核——**工具的作用是让"哪里可能有问题"变得可见**。

## 已知限制

- 术语与注释依赖人工维护的知识库，术语表没覆盖的领域需要先建库。
- 扫描版 PDF（纯图片）无法抽取文字，需先 OCR。
- 长文档翻译受模型上下文长度限制，靠切块规避，但跨块指代仍可能丢失。
